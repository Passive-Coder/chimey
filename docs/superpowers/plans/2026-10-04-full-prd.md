# Full Chimey PRD Implementation Plan

> Execute task by task in this session using superpowers:executing-plans. Each stage must produce working code, verification evidence, and a sequential commit/push. No delegated agents are needed.

**Goal:** Implement every requirement in docs/PRD.md, keeping the project named chimey.
**Architecture:** Flutter owns accessible presentation and persistent enrollment/rule management. Android's first-party Kotlin microphone foreground service owns PCM capture, LiteRT classification/personal matching, and action execution when Flutter is inactive. Native audio LLM inference and explicitly authorized internet assistance propose explanations without executing unvalidated rules. Other platforms need capability detection and independently verified equivalents rather than compatibility claims.
**Tech stack:** Dart/Flutter, Kotlin/Android AudioRecord, LiteRT YAMNet, LiteRT-LM audio-enabled Gemma, Node.js internet-assistance server. No Python.
**Spec:** docs/PRD.md (the supplied attachment has 95 lines and ends after section 4, story 2).

## Global constraints

- Flutter and Dart for the application.
- TensorFlow Lite technology for local sound processing.
- An audio-capable LLM executes on the mobile device in the full-feature configuration.
- Internet connectivity helps identify and contextualise unfamiliar sounds.
- Continuous live recognition and responsive actions.
- No Python in application code, backend services, model preparation scripts, training, evaluation, or build steps.
- Preserve the Apple Intelligence-style audio-reactive UI. Do not claim direction is measured with a mono microphone.

## Review focus

1. Similar appliance beeps must abstain instead of assigning unproven appliance identity.
2. Permission denial, interruption, and background starts must report accurate listening state.
3. Process death and restart must preserve profiles/rules and deduplication state.
4. Offline/LLM-unavailable devices must retain acoustic recognition and accurately report explanation availability.
5. Internet assistance must require explicit clip-sharing consent and separate audio hypotheses from research citations.
